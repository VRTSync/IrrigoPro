## 1. `hidePercent` must also gate the accessibility attribute — the crew view leaks the percentage today

#2009 says splitting `hidePercent` out of `hideDollars` "must not change what the crew view renders." That is correct as far as it goes, and it is not far enough.

`hideDollars` currently gates three things in `BudgetBar`:

- `:134` — whether the "over" pill reads `Stop — 116%` instead of `Stop`
- `:157` and `:162` — the dollar amounts row
- `:214` — the segment legend

It does **not** gate `:175`:

```
aria-valuenow={rawPercent !== null ? Math.round(Math.min(rawPercent, 100)) : undefined}
```

On the crew view, `rawPercent` is `(fillPercent / 100) * 100` — the fill percentage itself, because that surface fakes `allocation={100}`. So a screen reader on a field tech's phone announces the exact budget percentage, on the one surface designed so that no percentage is shown. Task #1866's rule was explicit: no dollar figure, and no percentage, because a percentage of a hidden number is a leak by inference.

**Required:** `hidePercent` gates `aria-valuenow` as well as the visible percentage. When it is on, omit the attribute rather than passing a rounded value. The `aria-label` already reads from `pillLabel`, so it is safe once the pill percentage is suppressed — confirm that rather than assume it.

**Add to the crew-view step:** assert on the rendered output that neither a visible percentage nor `aria-valuenow` is present. A test that only checks visible text passes this bug.
