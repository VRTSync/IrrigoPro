## What & Why

A field tech's "Submit & Bill" dialog shows a different total from the WC Snapshot the submit
creates. Artisan Pines HOA, submitted 2026-09-28 (Brady Mangel): the tech confirmed
**Labor $935.00 / Total $1,482.15**. The snapshot billed **Labor $2,044.25 / Total $2,638.90**.

The bill is correct. The dialog runs its own separate copy of the math and has not been updated
since May:

- **Dialog** — `previewWetCheckSubmit`, `artifacts/api-server/src/storage.ts:9395-9458`. Labor is
  `Σ finding.laborHours × rate` (`:9437-9446`). One finding of 3 heads counts 0.25 h.
- **Bill** — `_writeRepairedInFieldBilling`, `storage.ts:9486-9700`. Labor is
  `(wc.totalLaborHours + Σ zone.repairLaborHours) × rate` (`:9552-9575`). The zone hours are
  catalog `defaultLaborHours × quantity` per finding (`_recomputeZoneRepairLaborIfAuto`,
  `:9792-9836`), or the zone's manual value when `repairLaborManuallySet` is true. 3 heads = 0.75 h.

The two copies drifted when Task #753 (2026-05-20), Task #891 (2026-05-24) and the quantity fix
(2026-05-31, `84a457bd`) changed only the bill. This ticket removes the second copy: one
calculator, called by both the preview and the submit.

## Design context (locked decisions — do not relitigate)

1. **The bill's formula is correct and is the one that survives (decided).** Catalog hours ×
   quantity per zone, manual zone value when set. The preview adopts it. No billed number changes.
2. **One calculator, two callers — no mirrored copy (decided).** The preview must call the same
   function the submit calls. A comment saying "mirrors submit" is exactly what failed last time.
3. **Parts use the existing `computeWetCheckBillingPartsSubtotal`** (`wet-check-billing-view.ts:192-199`)
   in both callers. It is already the parts rule for the WC Snapshot quantity editor (#2000). The
   submit's own `lines` calculation (`storage.ts:9527-9540`) is deleted. It gives identical results
   for every finding the routes can create: the create route forces `noPartNeeded=false` whenever a
   part is set (`routes/routes.ts:17775`).
4. **The billable-finding rule is shared.** Today the submit uses `canAutoBill` (`storage.ts:9269-9272`,
   includes `LABOR_ONLY_ISSUE_TYPES`), but the preview uses a narrower filter (`:9427`, omits labor-only
   types). Both switch to one exported predicate.
5. **`wc.totalLaborHours` stays in the formula for this ticket (decided, deferred).** Nothing in the
   app writes it for a wet check. The create body (`routes/wet-check-create-gate.ts:12-23`) and the
   PATCH body (`routes/routes.ts:17281-17285`) do not accept it, so it is always `0.00`. Removing it
   touches four billing sites and three display sites; that is a separate cleanup ticket. Here the
   calculator takes it as an input so preview and bill stay equal even if it is ever non-zero.
6. **The append branch (`priorWcbId != null`, `storage.ts:9578-9640`) is not touched.** It runs only
   on manager conversion of an already-billed wet check, never from the tech's submit.
7. **Mode scope: service only in effect; inspection unchanged.** Inspection findings are never
   `repaired_in_field`, so their preview is all zeros today and stays all zeros.

## Steps

1. **Create `lib/shared/src/wet-check-labor.ts`** and add `export * from "./wet-check-labor.js";` to
   `lib/shared/src/index.ts`. It holds the one piece of arithmetic both the server and the field
   screen (Slice 2) need, so neither keeps its own copy:

   ```ts
   /** Catalog labor for one finding: perUnit × qty. qty NaN/null/< 1 counts as 1; bad perUnit = 0. */
   export function catalogLaborHours(
     perUnit: string | number | null | undefined,
     quantity: number | string | null | undefined,
   ): number;
   ```

   Moved from `storage.ts:9824-9832` exactly: `parseFloat(String(perUnit)) || 0` times
   `(isNaN(q) || q < 1 ? 1 : q)` where `q = typeof quantity === "number" ? quantity : parseInt(String(quantity ?? "1"), 10)`.

   **Then create `artifacts/api-server/src/lib/wet-check-repair-totals.ts`** (performs no queries):

   ```ts
   import { resolveIssueTypeKey } from "../seeds/issue-type-configs";
   import { computeWetCheckBillingPartsSubtotal } from "../wet-check-billing-view";

   export type LaborCatalog = Map<string, string | null>; // resolved issueType -> defaultLaborHours

   export function buildLaborCatalog(
     configs: Array<{ issueType: string; defaultLaborHours: string | null }>,
   ): LaborCatalog;
   // new Map(configs.map(c => [resolveIssueTypeKey(c.issueType), c.defaultLaborHours]))

   /** Catalog hours for one finding: perUnit × qty; qty that is NaN or < 1 counts as 1; unknown type = 0. */
   export function catalogLaborHoursForFinding(
     f: { issueType: string; quantity: number | null }, catalog: LaborCatalog,
   ): number;

   /** Auto zone hours = Σ catalogLaborHoursForFinding over every finding in the zone. */
   export function computeAutoZoneRepairLaborHours(
     findings: Array<{ issueType: string; quantity: number | null }>, catalog: LaborCatalog,
   ): number;

   /** Submit's billability rule. Moved verbatim from storage.ts:9269-9272. */
   export function canAutoBillFinding(
     f: { partId: number | null; noPartNeeded: boolean | null; issueType: string | null },
     laborOnlyTypes: ReadonlySet<string>,
   ): boolean;

   export type RepairTotals = {
     partsSubtotal: number; laborHours: number; laborSubtotal: number; grandTotal: number;
   };

   export function computeRepairedInFieldTotals(input: {
     billed: Array<{ zoneRecordId: number; noPartNeeded: boolean; partPrice: string | null; quantity: number | null }>;
     zones: Array<{ id: number; repairLaborHours: string | null; repairLaborManuallySet: boolean }>;
     zoneFindings: Map<number, Array<{ issueType: string; quantity: number | null }>>;
     catalog: LaborCatalog;
     wcBaseLaborHours: number;
     laborRate: number;
   }): RepairTotals;
   ```

   `computeRepairedInFieldTotals`: for each unique `zoneRecordId` in `billed`, zone hours = the zone's
   stored `repairLaborHours` when `repairLaborManuallySet`, otherwise
   `computeAutoZoneRepairLaborHours(zoneFindings.get(id) ?? [], catalog)`. Each zone counts once.
   `laborHours = wcBaseLaborHours + Σ zone hours`. `partsSubtotal =
   computeWetCheckBillingPartsSubtotal(billed)`. `laborSubtotal = laborHours × laborRate`. No rounding
   inside; callers `.toFixed(2)` exactly as they do today.

   `catalogLaborHoursForFinding` = look up `catalog.get(resolveIssueTypeKey(f.issueType))`; missing
   entry → 0; otherwise `catalogLaborHours(entry, f.quantity)` from `@workspace/shared`.

3. **Add one storage loader** in `storage.ts`, directly above `previewWetCheckSubmit`:

   The `wetCheckId` and `companyId` filters are the tenancy guard (Rule 1); both are required.
