# BUILD — Irrigation Build-Out, Slice 1: Zone Records Are the Truth

This is a single self-contained task. Build exactly what is described. Do not deviate, do not re-decide the locked decisions, and do not pull in Slice 2 (tile redesign) or Slice 3 (grid entry). This slice changes no page layout. It makes the data behind the existing irrigation profile honest, so the 38 chips on a tile and the zone table beneath it describe the same 38 zones.

## What & Why

Villas at the Boulders, `/customers/:customerId/irrigation-profile`. Controller A's tile shows 38 chips and the stepper reads 38. Expanded, its Zones table is empty. The wet check and the field location picker both offer zones 1-38.

A controller's zones live in two places that nothing keeps in step:

- `irrigation_controllers.total_zones` (`lib/db/src/schema/schema.ts:1933`), a bare integer. The chips (`artifacts/irrigopro/src/components/customers/irrigation-controller-grid.tsx:1538`), the stepper, the wet check, and the location picker all read it.
- `irrigation_profile_zones` rows (`schema.ts:1991-2028`). Only the expanded Zones table reads them.

Seven paths write one without the other:

1. `createIrrigationController` (`artifacts/api-server/src/storage.ts:11588-11630`) stores `totalZones` and creates no rows.
2. `updateIrrigationController` (`storage.ts:11632-11722`) seeds or trims rows only when the old and new counts are both numbers (`:11668`, `:11694`). Null → 38 creates nothing.
3. `PATCH /api/properties/:customerId/controllers` (`artifacts/api-server/src/routes/routes.ts:16420-16475`), which the wet-check stepper calls (`artifacts/irrigopro/src/pages/wet-checks/ControllerHeader.tsx:31`), writes `totalZones` with a raw `db.update` (`:16450-16453`). No rows, no history.
4. `createIrrigationZone` / `deleteIrrigationZone` (`storage.ts:11833-11859`, `:11896-11924`) never change the count.
5. Shrinking deletes only empty rows (`storage.ts:11663-11691`), so rows with data survive above the count.
6. Zone number is editable (`irrigation-controller-grid.tsx:912-920`; `updateZoneBody`, `artifacts/api-server/src/routes/irrigation-profile-routes.ts:111`), so rows can be renumbered past the count or leave gaps.
7. CSV import sets the count to the highest zone number for new controllers (`storage.ts:12206`) but to the row count in Replace mode (`:12219-12224`), and Replace mode hard-deletes zones (`:12384-12388`).

This ticket puts every count change behind one function that writes the rows and the count together, then backfills existing controllers.

## Locked decisions (do not relitigate)

1. **Zone records are the truth (decided, Randy 2026-10-05).** For every controller, its non-retired zone rows are exactly zones `1..total_zones`, no gaps. `total_zones` is null only when the controller has no non-retired rows (not set up yet).
2. **Lowering the count retires zones; nothing deletes a zone (decided, Randy 2026-10-05).** Retired = `retired_at` set. Retired zones keep every field. Raising the count again restores the same row with its data.
3. **`retired_at` is not the existing `is_active`.** `is_active` is the user's "Needs attention" status (`irrigation-controller-grid.tsx:861-868`) and is unchanged.
4. **`total_zones` stays for now, written in one place only.** Slice 4 moves its readers to zone rows and drops the column. Until then only `_reconcileControllerZones` writes it.
5. **Zone numbers are not editable.** They are positions 1..N. To add a zone you raise the count; to remove one you lower it (it retires from the top).
6. **Count range is 1-100**, matching `MIN_ZONES` / `MAX_ZONES` (`irrigation-controller-grid.tsx:73-74`) and the wet-check body (`routes.ts:16423`).
7. **Field techs may change the count (decided).** They can today via the wet check (`isFieldRole`, `routes.ts:16428`). The field is where a missed zone gets found (Rule 4). Same function, same history entry.
8. **Wet-check mode scope: both modes, identical.** The only wet-check change is the PATCH route at item 3 above. It has no mode branch before or after.

## Out of scope

- Any layout or visual change (Slices 2-3). The only client changes here remove calls to deleted endpoints.
- What pickers, wet checks, documents or invoices read (Slice 4 onward).
- Site maps. Do not read or write `controllers`, `irrigation_zones`, `/site-maps`, or `/customers/:id/site-maps`.

### 2. Storage — one reconcile function

In `storage.ts`, next to `_appendIrrigationSnapshot` (`:11362`), add:

```ts
/**
 * The only writer of irrigation_controllers.total_zones. Makes the controller's
 * non-retired zones exactly 1..target: restores retired rows at or below target,
 * inserts placeholders for missing numbers, retires rows above target.
 * Runs inside the caller's transaction. Returns the zone numbers it touched.
 */
async _reconcileControllerZones(
  q: DbExecutor,              // existing type used by _appendIrrigationSnapshot (storage.ts:11363)
  ctrl: IrrigationController,
  target: number,             // 1..100, validated by the caller
  actor?: { id: number; name: string },
): Promise<{ created: number[]; restored: number[]; retired: number[] }>
```

Behaviour, in this order:

1. Throw `new RangeError("zone count must be 1-100")` if `target` is not an integer in 1..100.
2. Load every row for `ctrl.id` (retired or not), keyed by `zoneNumber`.
3. For `n` in `1..target`: if a row exists with `retiredAt` set, update it to `retiredAt: null, retiredByUserId: null, retiredByName: null` → `restored`. If no row exists, insert `{ companyId: ctrl.companyId, controllerId: ctrl.id, zoneNumber: n, name: \`Zone ${n}\`, zoneType: "other", runTimeMinutes: 0, zoneOrder: n, isActive: true }` → `created`.
4. For every row with `zoneNumber > target` and `retiredAt` null: set `retiredAt: new Date(), retiredByUserId: actor?.id ?? null, retiredByName: actor?.name ?? null` → `retired`.
5. Update the controller: `totalZones: target, lastUpdatedAt/updatedAt: now`, plus `lastUpdatedByUserId/Name` from `actor`.

Then add the public method, and declare it on the storage interface beside `updateIrrigationZone` (`:1363`):

```ts
async setControllerZoneCount(
  companyId: number | null, controllerId: number, target: number,
  actor?: { id: number; name: string },
): Promise<{ controller: IrrigationController; created: number[]; restored: number[]; retired: number[] } | null>
```

It opens `db.transaction`, loads the controller with the tenant condition used at `:11640-11646` (null → return null), calls `_reconcileControllerZones(tx, …)`, re-reads the controller, and calls `_appendIrrigationSnapshot` with summary `Zone count ${old ?? "not set"} → ${target}` followed by any of `; added zones a-b`, `; restored zones a-b`, `; retired zones a-b (history kept)`. Ranges are compressed (`31-38`, `4, 7`).

### 3. Route every count write through it

- **`createIrrigationController` (`storage.ts:11588-11630`).** Wrap each insert attempt in `db.transaction`. Insert with `totalZones: null`. If `data.totalZones` is a number, call `_reconcileControllerZones(tx, inserted, data.totalZones)` in the same transaction. Keep the 23505 retry loop around the whole transaction. `createControllerBody.totalZones` (`irrigation-profile-routes.ts:72`) becomes `z.coerce.number().int().min(1).max(100).nullish()`.
- **`updateIrrigationController` (`storage.ts:11632-11722`).** Remove `totalZones` from the `.set({...patch})` spread. If `patch.totalZones` is a number and differs from `before.totalZones`, call `_reconcileControllerZones(tx, updated, patch.totalZones, actor)` after the update. If `patch.totalZones === null` and `before.totalZones != null`, throw `new ZoneCountClearError()` (exported class in `storage.ts`); the PUT route (`irrigation-profile-routes.ts:397-468`) maps it to 400 `{ message: "A zone count can't be cleared. Lower it instead — zones above the new count are retired and their history is kept." }`. Delete the trim/seed block `:11663-11717` entirely. `updateControllerBody` inherits the new 1-100 rule.
- **`ensureIrrigationControllers` seed loop (`storage.ts:11526-11542`).** Replace the loop with `await this._reconcileControllerZones(db, inserted, config.zoneCount)` under the same `if (inserted && config.zoneCount != null)`.
- **Wet-check PATCH (`routes.ts:16420-16475`).** When `zoneCount !== undefined`, call `storage.setControllerZoneCount(cid, ctrl.id, zoneCount, actor)`, with `actor` built from `req.authenticatedUserId` via `storage.getUser` (as in `irrigation-profile-routes.ts:330-331`). Notes still go through the existing update, now via `storage.updateIrrigationController(cid, ctrl.id, { notes }, actor)`, not raw `db.update`. Delete `:16446-16453`. The response shape is unchanged.
- **CSV import (`importIrrigationProfile`, `storage.ts:11939-12435`).**
  - Diff (`:12100-12131`): build `existingZones` from non-retired rows only, so a retired zone is never listed for removal.
  - New controllers (`:12206`): insert with `totalZones: null`. After the zone inserts, call `_reconcileControllerZones(q, newCtrl, max zone number in file)`, which fills gaps with placeholders. If the file has no zones for the controller, skip it (the count stays null).
  - Existing controllers (`:12219-12233`): delete the `newTotalZones` calculation and the `ctrlPatch.totalZones` line. After the zone upserts, `target = isReplaceMode ? maxInputZone : Math.max(maxInputZone, existingCtrl.totalZones ?? 0)`; if `target >= 1`, call `_reconcileControllerZones(q, existingCtrl, target, actor)`.
  - Replace-mode removal (`:12384-12388`): delete the hard `delete(irrigationProfileZones)`. For each id in `zoneIdsToRemove` whose `zoneNumber <= target`, reset it to the placeholder values from step 2.3, keeping `retiredAt` null. Rows above `target` are retired by the reconcile call. Program removal (`:12390-12394`) is unchanged; the FK's `on delete set null` (`schema.ts:1999`) clears program links on retired rows.
