# FIX — Invoices Page: Search Keeps Focus, and No Auto-Applied Filters

This is a single self-contained task. Two defects on `/invoices`, one commit. Do not deviate from the decisions below; where this spec gives exact code, use it.

## What & Why

**Part A — the search box loses focus after every letter.** The box is already debounced (250 ms) and server-applied (Task #1942). The defect is what happens when the debounced value lands: the search writes `?search=` to the URL, the list query key changes, `useInfiniteQuery` has no data for the new key, `isLoading` goes true, and the page hits the early return at `artifacts/irrigopro/src/pages/invoices.tsx:2152`:

```tsx
if (isLoading) {
  return ( <div ...><Loader2 .../> Loading invoices...</div> );
}
```

That return replaces the whole page — header, aging strip, and the filter bar holding the `<Input>` — with a spinner. The input unmounts, focus is gone, and when the results arrive a fresh input mounts with the text but no cursor. The `if (error)` return at `:2161` has the same shape. Every pause in typing longer than 250 ms costs the user their place.

**Part B — filters apply themselves on arrival.** `invoices.tsx:809-821` applies `COLLECTIONS_DEFAULT_QUERY` (`lib/invoice-ar-query.ts:144`: `aging: "overdue"`, `paymentStatus: "unpaid"`, `sort: "balanceDue"`, `dir: "desc"`) on mount whenever the URL is empty, for every invoice-reading role (`COLLECTIONS_LANDING_DEFAULT`, `lib/shared/src/roles.ts:267`). "Clear all" (`invoices.tsx:2233`) also resets to that default rather than to nothing, so the user cannot actually clear the filters.

## Done looks like

- Typing "woodglenn" at normal speed, with pauses, never moves the cursor out of the box. The header, aging strip and filter bar never disappear while results load.
- While a search is in flight, a small spinner shows inside the search box and the rows already on screen dim; they are replaced when the new rows arrive.
- Enter applies the search immediately. Escape or the X button clears it immediately.
- Typing a search does not add one browser-history entry per pause.
- Opening `/invoices` with no query string shows every invoice, unfiltered, newest-first grouped by billing month. URL stays `/invoices`. No chips.
- "Clear all" returns to that same unfiltered view, for every role.
- Deep links (`?aging=days90Plus`, `?month=…`, `?customerId=…` from Financial Pulse) still open exactly as before.

## Locked decisions

1. **The toolbar never unmounts.** Loading and error states render in the list area below the filter bar. No early return in `InvoicesPage` may sit above the header/strip/filter bar.
2. **Previous results stay on screen during a refetch** via TanStack v5 `placeholderData: keepPreviousData` (repo is on `@tanstack/react-query ^5.90.21`) on both the list query and the aging-summary query, so the header total and strip don't blank either.
3. **Debounce stays at 250 ms.** The bug was the unmount, not the delay.
4. **No landing default of any kind** — no filters and no sort. The page opens on `EMPTY_AR_QUERY`. A sort is still one click away in the Filters popover or a column header.
5. **Retire the landing-default machinery entirely** (project rule: no dead weight left behind). `COLLECTIONS_DEFAULT_QUERY`, `COLLECTIONS_LANDING_DEFAULT`, `UiDefaultRoles`, `usesUiDefault` and the type-safety test guarding them have no other consumer (verified by `git grep`); all are deleted.
6. Server, URL parameter names, chips, and the `?aging=overdue` filter value are untouched. "Any overdue" stays selectable; it just isn't applied for you.

## Out of scope

- Server search behaviour (`invoice-list-routes.ts`), what fields search matches.
- The Filters popover contents, the aging strip, row expansion.
- `components/billing/invoice-list.tsx` (separate component; not this page).
